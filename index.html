什么是 Harness？

// 通俗理解
大模型是一匹烈马，Harness 就是套在它身上的整套马具
缰绳（指令）只是其中一件 —— 配齐整套马具，才管得住这匹烈马
// 精确定义
模型权重之外的一切工程基础设施
💡 Harness 不是让模型更聪明，而是让模型更懂得工作

用AI编程时，你是不是也经历过这些？

🎲

自由发挥

“优化一下，把整个模块重写了”
本质 · 需求理解不一致
🔁

来回折腾

“改好A，坏了B”
本质 · 过程完全失控
🤷

说了不算

“AI说跑通了，一运行全是报错”
本质 · 没有判定标准
💡 这不是模型不够强，是缺了一套“管住它的规矩”

Harness 的五个子系统

01
指令子系统
INSTRUCTION
管 「做什么」
系统提示词与工作流规范，
约束 AI 的行为边界与输出格式
system prompt · 工作流规范
02
工具子系统
TOOL
管 「用什么」
终端、编译器、测试框架，
让 AI 拥有可执行的能力
terminal · compiler · test
03
环境子系统
ENVIRONMENT
管 「懂什么」
术语表、代码结构、架构知识，
让 AI 真正懂你的项目
glossary · architecture
04
状态子系统
STATE
管 「记什么」
记录干到哪一步、改了什么，
全程可追溯
change log · task list
05
反馈子系统
FEEDBACK
管 「判什么」
测试验证，
判定「是否完成」的唯一依据
test · regression
💡 五个子系统并行协作，共同构成完整 Harness
